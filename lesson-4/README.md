# Урок 4: Контейнеризація вебзастосунку (Django + PostgreSQL + Nginx)

Цей репозиторій містить локальне середовище розробки на базі Docker Compose, яке відповідає вимогам 4 завдання.

## 📦 Структура проєкту

Проєкт складається з трьох контейнерів:
1. **`web`** (Django) — вебзастосунок на базі Python (Gunicorn).
2. **`db`** (PostgreSQL) — база даних.
3. **`nginx`** (Nginx) — вебсервер (reverse-proxy), який приймає зовнішні запити на 80 порту і перенаправляє їх на Django (порт 8000).

## 🚀 Інструкція із запуску

Для запуску проєкту на вашому комп'ютері має бути встановлений **Docker** та **Docker Compose**.

1. Перейдіть до папки проєкту:
```bash
cd lesson-4
```

2. Запустіть контейнери у фоновому режимі (білд образів та застосування міграцій відбудеться автоматично):
```bash
docker-compose up -d --build
```

3. Відкрийте браузер і перейдіть за адресою:
[http://localhost](http://localhost)

Ви повинні побачити повідомлення: `Hello from Django in Docker Compose!`. Це означає, що запит успішно пройшов через Nginx до Django.

## 🛠 Технічні деталі налаштування

- **Міграції бази даних:** У `Dockerfile` налаштовано автоматичний запуск `python manage.py makemigrations` та `python manage.py migrate` перед стартом сервера `gunicorn`. Це гарантує готовність БД при старті контейнера.
- **Підключення до DB:** Завдяки файлу `.env` та налаштуванням у `settings.py`, Django підключається до хоста `db` (назва сервісу в Docker Compose) замість локального SQLite.
- **Мережа Docker:** Усі 3 сервіси знаходяться в одній дефолтній мережі Docker Compose, що дозволяє їм легко бачити один одного за іменами сервісів (`http://web:8000`).

## 🧹 Зупинка та очищення

Щоб зупинити контейнери і видалити томи (дані з БД буде видалено):
```bash
docker-compose down -v
```
